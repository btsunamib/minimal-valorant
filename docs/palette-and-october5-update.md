# 原生材质、敌方描边与 10 月 5 日资源包

人物全黄的问题已在真实 EGL/OpenGL 光栅中重现。GoldSrc 三角命令是顺时针，原导入器直接交给使用逆时针正面的 Three.js，黄色反面外壳因此成了可见表面。修正三角扇与三角条带的朝向后，再用身体的 stencil 遮罩排除衣服、头发和重叠表面的内部像素。主 WebGLRenderer 明确申请 stencil 缓冲；地图深度测试和原骨骼动画保留。

原生模型的调色板贴图已有明暗信息。原先还经过强 PBR 灯光、白色自发光和 ACES，容易丢失原色。现在原生实体和补色手部使用纹理/顶点颜色的 MeshBasicMaterial，关闭 tone mapping；原始加色、透明、裁切贴图模式保留。原生光效使用正确的面朝向并剔除背面，避免内向光效外壳的两面一起加亮整个武器。地图材质与光照未改动。

资源包导入为可直接解码的原始 IDST v10，不重新建模、不缩小高清贴图。使用确定性 gzip 保存完整模型字节，源文件与输出 SHA-256 见 `october5-resource-sources.json`。

验证：99 项 Node 单元测试通过；实际 main 模块对局、导入武器、收藏页集成检查通过；六张 BSP 地图的 26 条物理路线通过。集成检查模拟 DOM/Canvas，不能替代真实浏览器画面。

EGL/OpenGL 使用实际 Three 骨骼采样后的模型、原始 RGBA 调色板和同一外壳，测试六名人物的前、侧、后三个视角。旧朝向平均有 96.89% 的身体像素被黄色覆盖；修复后 18 个样本的身体内部黄色覆盖均为 0。所有实体像素都来自原始贴图调色板。数据与前后图见 `verification/native-opengl-results.json` 和 `verification/native-opengl-winding.jpg`。此测试用 Mesa llvmpipe 的真实 OpenGL 深度、剔除、stencil 操作，并非特定手机 GPU 的 WebGL 认证。

线上发现入口更新后，未带版本号的 rules 与描边模块仍可能命中旧缓存。现在整个应用的本地模块导入和收藏页样式都使用同一个版本；未改动的 Three/fflate 供应包继续复用。浏览器模块版本统一更新为 `20261005-palette6`，避免旧导入器或旧材质函数继续复用。
